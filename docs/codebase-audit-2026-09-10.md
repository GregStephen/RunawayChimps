# Codebase reliability audit — September 10, 2026

**Base:** `main` at `c388d87c0443158011dd9b1ba5ef9c005cc44267` (merged PR #3). **Fix branch:** `codex/codebase-reliability-audit`. **Status:** implemented source changes; Unity and device validation pending. This audit does not assert that every possible defect has been found or that the game is ready to release.

Greg requested a thorough code review, a new branch from main, fixes, and a committed/pushed result. The review covered all 95 original first-party/customized PhotonVR C# files, the four enabled scenes and their serialized component references, four PhotonVR runtime prefabs, build registration, package configuration, and relevant bundled Photon/PlayFab API definitions. Two new C# files bring the checked total to 97. Third-party SDK internals and cloud services were not comprehensively audited. Scene meshes, imported animation/rig quality, NavMesh geometry and headset performance cannot be established by source inspection.

## Implemented fixes

P1 means a gameplay/session blocker; P2 means a reliability or maintenance defect. These severities describe the source risk, not measured frequency on a headset.

| ID | Priority | Confirmed defect | Change on this branch |
| --- | --- | --- | --- |
| A01 | P1 | `LoadSceneOnStart.Awake` can replace Bootstrap before other objects finish Awake and become persistent. Bootstrap also starts authentication from Awake. | Scene replacement and sign-in begin in Start, after singleton/persistence initialization. Duplicate bootstrap instances are rejected. |
| A02 | P1 | Authentication sets its run guards before starting and never clears them on failure. There is no timeout or usable retry path. | Guarded attempts, 30-second default timeout, failure reset, stale-continuation rejection, and reuse of successful sign-in on Photon reconnect. Reconnecting does not call the login reward again. Existing identity IDs are preserved. |
| A03 | P1 | Startup can wait forever; errors only reach logs/status events, and Loading can reset readiness flags after another component has already set them. | Loading retains stage state, displays failures in its existing text, offers trigger/R retry, bounds startup waits, and reuses an outstanding native Hub load. Missing scenes/services fail explicitly. |
| A04 | P1 | Room joining lacks disconnect/create-failure cleanup; public no-match clears the busy state before fallback creation finishes; repeated input overwrites intent. | One pending request through completion, 30-second default timeout, rejected-operation handling, duplicate-request suppression, explicit failure text, and disconnect/create-failure cleanup. |
| A05 | P1 | Private joining from disconnected state races the manager's automatic public join. | The manager defers to RoomSwitchService while its request is pending, regardless of callback order. The terminal displays joining/failure state. |
| A06 | P1 | Old local-avatar readiness survives a room change; visual-settle work can wait indefinitely on animated material changes. | Leaving clears player readiness, spawning can be retried, reporting restarts on enable, and visual settling is bounded to eight seconds. Readiness republishes the loaded sector; room reconnection preserves the physical location's zone. |
| A07 | P1 | Hub grounding uses a guessed capsule offset, can hit the rig itself, and does not reset locomotion history after snapping. | Grounding uses the actual capsule bounds and Hub floor hits, excludes the rig, preserves Rigidbody mode, resets hand/velocity history, and reports missing floor instead of marking setup ready. |
| A08 | P1 | Seven MonoBehaviour filenames differ from their declared classes, including active hand, keyboard/UI, tile and keycard components. | Rename each script with its existing `.meta` GUID. Classes and serialized field identities stay unchanged. KeyCard1 becomes KeyCard; the previous KeyCard file becomes VRKeyCard. |
| A09 | P1 | The alternate physical keyboard handler used by 40 Hub keys accepts remote hands and keeps stale press state after collider disable. | Require LocalRigMarker, clear disabled/destroyed pressing colliders, and reset on disable. |
| A10 | P1 | Bootstrap's smooth-turn action has no bindings. The script also rotates around the body rather than the tracked head and does not turn locomotion history. | Use the configured action when bound, otherwise read the right XR thumbstick; use Player.Turn for the locomotion body; preserve externally enabled actions. |
| A11 | P1 | Monster snapshots/controller state persist when room actor numbers are reused; disabled/re-enabled navigation can retain stale authority state. | Clear snapshots on room identity changes, reset navigation on disable, reject non-finite network poses/times, and restrict state requests to players in that sector. |
| A12 | P1 | Chase eligibility only refreshes on the detection timer; null patrol points can throw; capture has no explicit safe-zone check. | Revalidate the target's sector/vent eligibility every update, clear the old chase path, skip missing patrol points, and restrict the active capture path to Containment vents. Closest-player targeting is preserved. |
| A13 | P2 | MonsterActivationGate does not refresh after re-enable and can gate shared AI using one client's local zone. | Reapply local presentation state on enable; synchronized navigation/authority are excluded from local-zone gating. |
| A14 | P2 | Draining an unrelated held preload for travel activates it without cleaning it up; a preload trigger marks itself done even when no load starts. | Abandon/drain/discard unrelated pending preloads and return an acceptance result to the trigger. Native loads are still not cancellable. |
| A15 | P1 | Legacy PhotonVR SwitchScenes helpers change rooms during scene travel. | Route them through SectorTravelService and its supported destinations, preserving the current room. Their capacity argument is retained for call compatibility. |
| A16 | P2 | Containment is registered twice in enabled Build Settings. | Remove the duplicate; keep Bootstrap/Loading/Hub/Containment at indices 0–3. The Editor validator now detects duplicate registration and missing scripts. |
| A17 | P2 | Cosmetic snapshots only apply nonempty entries, so removing a slot can leave a hat equipped. Saved dictionaries are not flushed and empty saves deserialize a blank key. | Apply every cosmetic slot, including removed/empty slots; delete obsolete saved values, ignore blank keys and save PlayerPrefs. |
| A18 | P2 | Avatar updates assume all rig references exist, JSON is valid, and head-derived quaternion components form a valid yaw rotation. | Guard missing references and malformed colors; calculate body/name yaw with normalized rotations and avoid zero-direction LookRotation. Use the PUN Realtime application ID in editor defaults. |
| A19 | P2 | Inventory loading reads only the first page/first currency stack and treats zero-amount entries as owned. CloudScript transport success can contain an execution error. | Shared paginated loader, complete-snapshot publication, stack totals with overflow protection, positive-amount ownership, stale-refresh rejection, repeated-token protection, and execution-error reporting. Both login paths use the loader. |
| A20 | P2 | Face animation divides by zero with no talking faces and accesses material index 2 when there are only two slots. Repeated material access unnecessarily clones slots. | Guard empty faces and the actual slot bound; use shared-material bindings and skip unchanged swaps. |
| A21 | P2 | Zone-specific proximity can stay active when local zone becomes None. ZoneDebugHUD accesses GUI.skin from Awake. | Clear zone-specific proximity for None/transition state; create IMGUI style inside OnGUI. Unzoned Hub interactions keep their existing behavior. |
| A22 | P2 | A zero-sized velocity history or zero delta time produces invalid locomotion arithmetic; duplicate players still initialize after being rejected. | Clamp the history size, index the allocated buffer, ignore zero-duration samples, and return immediately for duplicates. |
| A23 | P2 | Vent graph traversal crashes on null links or neighbors outside the registered graph. | Ignore missing/external links and clear the singleton on destruction. This does not generate the missing active-level graph. |
| A24 | P2 | Hand animation assumes a local PhotonView/animator/device and advances thumb pose per frame. Item recovery always re-enables even an originally disabled grab component. | Resolve missing hand PhotonViews from their parent so remote hands retain ownership filtering; guard missing inputs, scale thumb movement by time (preserving the previous 60 Hz rate), and re-enable a recovered grab only if recovery disabled it. |
| A25 | P2 | Inspector join helpers use a separate 16-player/default queue setting; arbitrary capacity values wrap through byte casts. | Use the manager queue/capacity and clamp new-room requests to the confirmed ten-player limit. Existing rooms are not resized. |
| A26 | P2 | Suspending a headset can leave travel continuing with stale presence; later failure can leave a transition unclear. | Cancel an in-progress travel attempt on suspension and retain the pre-commit source zone for recovery. Real suspend/resume handover remains a required headset test. |
| A27 | P2 | Current docs call already-merged PR #3 an unpushed patch. | Record the merged main baseline and distinguish this audit's implementation from pending Unity/Photon/headset checks. |

## Validation evidence

**Executed here:**

- `python Tools/validate_source.py --syntax`: PASS for 97 first-party/customized PhotonVR C# files and four enabled scenes. Checks matching component filenames, script metadata/GUID uniqueness, C# syntax parsing, build registration, scene GUIDs, unique local object IDs and resolved local references.
- The same validator against a reconstructed copy of base `c388d87c` reports eight failures: the seven filename mismatches and duplicate enabled Containment scene. All eight are absent on the fix branch.
- Enabled-scene serialized objects checked: Bootstrap 107, Loading 33, Hub_Base 1,470, Level1_Containment 2,193. Scene geometry and scene object contents are unchanged by this audit.
- Existing script GUIDs are preserved through the seven renames; new C# files have new metadata. Relevant Photon operation return types and PlayFab pagination/error fields were checked against the SDK code committed in the repository.
- `git diff --check`: PASS. These are source/serialization checks, not compilation or runtime tests.
